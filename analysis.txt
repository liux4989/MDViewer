**Project Name**: Floating TOC (Table of Contents)
**Type**: Obsidian Community Plugin
**Version**: 1.0.0

## Architecture Analysis

### Layered Architecture Design
The project implements a sophisticated multi-layered architecture:

1. **Data Layer** (`datasources/`)
   - `ObsidianDataSource`: Raw Obsidian API access
   - `ObsidianEvents`: Event abstraction and debouncing
   - `Navigator`: Navigation capabilities

2. **Business Logic Layer** (`services/`)
   - `TocDataProcessor`: Data transformation and validation
   - `TocFileService`: File change coordination
   - `TocScrollService`: Scroll event handling
   - `TocEditService`: Edit event coordination
   - `TocServiceCoordinator`: Orchestrates all services

3. **State Management Layer** (`stores/`)
   - Split-store architecture with clear separation
   - `TocModeStore`: UI interaction state
   - `TocStore`: Document data and navigation
   - Atomic reducer pattern for predictable state updates

4. **UI Layer** (`components/`, `hooks/`)
   - Pure presentational components
   - Focused custom hooks for store access
   - Obsidian-themed styling with CSS variables

### Key Architectural Patterns

#### Event-Driven Architecture
- Decoupled event handling with proper debouncing
- Service coordination for complex workflows
- Clean separation between Obsidian runtime and business logic

#### Atomic State Management
- Single dispatch per business operation
- Immutable state updates via reducers
- Predictable state transitions

#### Dependency Injection
- Testable service layer with injected dependencies
- Store adapter pattern for service-store communication
- Context-based dependency provision
